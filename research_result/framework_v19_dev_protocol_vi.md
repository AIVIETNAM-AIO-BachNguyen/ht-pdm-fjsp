# V19 time-resolved capacity RL — prelocked DEV protocol

Locked before V19 implementation/outcomes. Proposal `v19_temporal_capacity_proposal_vi.md`; original user A/B, independent replication and one fresh frozen TEST are unchanged. No opened/reserved TEST is reused.

## Arms, metric and gate

Two scratch-RL arms: `temporal_deficit` versus equal-parameter/equal-compute `snapshot_deficit`, as formulated in the proposal. Both receive identical current 56-D observation, matching incidence, served flags, worker releases and nine-offset future-demand `D`; only the nine action-specific deficit inputs differ. All actions stay legal. Same initial network weights per paired seed. Use V17 full-matching rank-projection learning from old-policy full-H64 root costs on four common future scenarios per state, with assignment auxiliary λ0.5, temperature10, KL penalty1/hard whole-bank KL≤0.02, Adam3e−4, five epochs/minibatch64/gradient clip0.5; identical service-flow protection used by both V18 arms to avoid early WAIT collapse. No risk-Q blend, teacher imitation or policy pretraining. Save active parameter counts/initial digests, feature contracts, per-bank Q and trajectory hashes, occupancy profiles and gradient checks.

Primary final DEV statistic: paired equal-four-case H64 economic cost `temporal_deficit−snapshot_deficit` over 5 training seeds ×16 same final physical seeds. Hierarchical 20,000-draw percentile CI95 (resample five training seeds, then physical seeds within each sampled train seed), bootstrap seed73440000. **Go** only if mean ≤−10, CI upper<0, ≥4/5 per-seed means negative including ≥2/3 strongest control seeds; candidate ≤1.02× bounded rollout, ≥10× faster selection, no more costly than frozen V14 joint on this physical panel, and no risk or other simple heuristic dominating cost *and* runtime. This DEV go is stricter than mere component repair but is not full goal completion; original A requires ≥5% over strongest locked comparator with uncertainty or B requires within1% planner and ≥10× faster, then independent five-seed replication and a single fresh TEST.

## Verification and decision after DEV

Before full, test profile derivation against a separate combinatorial implementation at boundary cases: WAIT, duration2/9, worker already busy, interchangeable/reciprocal/specialist compatibility, newly reaching PM threshold, multiple simultaneous requests, and action exclusion. Compare candidate/snapshot exact feature equality except deficit slots and identical active parameter counts; check legal masks, Q common tapes, ranking, service flow, KL rollback, save/load, seed splits. On **already opened** V18 final DEV states, require >1% of sampled legal-multi-action states to have candidate deficit profile not equal to its snapshot vector before launching expensive training; this is a feature discrimination sanity check, not performance selection. Pass focused tests, Ubuntu smoke and independent smoke audit; commit/push source first. Record manifest Git/source/proposal/protocol/registry hashes, source physical roles, all Q banks/checkpoints/update traces/selection grid/final episodes/per-case operational metrics/compute/failures and bootstrap. Independent verifier replays selected source/Q banks and all selected learned final episodes plus frozen comparator checkpoints, seed/schema/metric arithmetic and gate. If DEV no-go, preserve negatives, do not open V19 replication/TEST; use failure evidence to choose a distinct next method. If DEV go, prelock and run disjoint five-seed replication, then at most one fresh frozen TEST with repeated-development caveat. Prior-art boundary in the proposal is provisional, and must be revisited before novelty claims.
