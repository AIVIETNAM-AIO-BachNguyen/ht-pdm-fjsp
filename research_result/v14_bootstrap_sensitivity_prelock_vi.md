This addendum is written while the V14 trainer is still in `training` and before any selected DEV cost or ablation summary is read. It leaves the original `framework_v14_dev_protocol_vi.md`, running campaign, source manifest and **prelocked H1/H2 gate** unchanged. No TEST is involved.

## Reason and fixed secondary calculation

The existing V14 runner and independent verifier implement a **crossed** paired bootstrap: each of 20,000 draws resamples five training-seed indices and one length-16 vector of physical-seed indices, applying that same physical-index vector to all selected training seeds. This respects the fact that all training replicas face the same 16 DEV physical seeds and pairs the two arms. The protocol phrase “resamples training seeds, then shared 16 physical indices within each seed” could also be read as a **nested** bootstrap: after selecting training seeds, independently resample 16 physical indices for each selected seed, still pairing candidate and control within each physical draw. Those two algorithms estimate different variation under the crossed seed-by-tape design. Their mean point estimate is identical; intervals can differ.

After the main V14 full independent audit PASS, compute the nested 20,000-draw percentile 95% CI for the same five-by-16 matrix of equal-case `competition−count_calibrated` H64 costs. Use fixed fresh seed **72640001**, drawing `(20,000,5)` training indices then `(20,000,5,16)` physical indices independently. Report the nested CI beside the original crossed CI, seed means, and whether its upper endpoint is below zero. Also report per-case nested CIs using the same resampling indices, with no new episodes, checkpoint choice, training or forecasts. Independently recompute from immutable episode rows and verify the matrix and quantiles. Treat this as sensitivity only: neither a favorable nested interval nor an unfavorable one may silently replace the original prelocked gate.
