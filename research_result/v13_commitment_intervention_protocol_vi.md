# V13 technician-commitment intervention — prelocked opened-DEV diagnostic

Locked before implementing or running the intervention. This follows the independently audited V13 exposure probe, which found excess capacity-constrained at-risk PM ticks in interchangeable scale1 and reciprocal scale2. It asks whether one earlier actor service commitment causally contributes to that later exposure under the same physical tape. This is a hindsight oracle diagnostic, not a deployable controller, scratch-RL method, or TEST confirmation. No V14 selected DEV scores enter this design.

## Source, intervention and estimand

Use only immutable audited V13 `framework_v13_dev_20261020T141536Z` competition checkpoints, five train seeds 72500000–04 and 16 opened DEV physical seeds 72510000–15. Primary target cases: interchangeable scale1 and reciprocal scale2. Report reciprocal scale3 and specialist/generalist scale2 as descriptive controls. Replay the deterministic actor's H48 choices, threshold requester and fixed H16 risk tail, reconciling H64 metrics to V13 `episodes.csv`.

For each original H48 trajectory, find the **earliest** tick τ at which any unstarted preventive request is unfailed, has `age+1 >= failure_age`, is not selected, and cannot be started in any legal matching at that tick. Tie target machine by smaller index. Among occupied technicians compatible with that target, select largest current `remaining` service ticks, tie smaller technician index. The request metadata at τ identifies the occupied machine and its original service start tick t0. Verify the original chosen matching at t0 contains exactly this (machine, technician) edge. On a fresh reset with the identical physical seed, at t0 replace that one original matching with the same matching minus that edge; leave any other simultaneous starts intact. At all other ticks choose the original selected actor deterministically from its current observation and legal mask. Apply only one such edit per episode. If no eligible τ or no occupied compatible technician exists, replay unchanged and count a no-op. Refuse any illegal edited matching or source-replay mismatch.

Primary estimand is mean paired H64 economic cost `edited−original` over **all** episodes, including no-ops, separately in the two target cases and jointly equal-weighted. Hypothesis: each target mean ≤−10, improvement in at least 4/5 training seeds per target, and paired hierarchical 95% CI upper <0 for each target. Resample five train seeds, then shared 16 physical indices inside each selected seed; 20,000 draws, fixed bootstrap seed 72540002. This is a directional mechanism gate on selected/opened DEV, not a success criterion for the user goal. Report no-op frequency and conditional-on-trigger effects without treating them as primary. If gate fails, do not claim the particular commitment is a material cause; if it passes, do not infer a practical reservation policy will work.

Secondary metrics: paired H48 at-risk PM exposure total/individually feasible/capacity constrained, H48 PM starts, failures, H64 failure cost, H48 availability, all four per-case costs, trigger τ, t0, selected technician/machine, service duration/remaining, fraction of edited starts that the actor later reissues, and episode/inference compute. Because an edited action can change later requests and actor actions, count full closed-loop continuation; never splice the original future trace into the edited trajectory.
