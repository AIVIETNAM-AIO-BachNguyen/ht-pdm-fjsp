# V16 conditional proposal — learned value of post-decision technician release

Status: **proposal only** after audited V15 feature-screening no-go. No V16 code, seeds, scratch-RL run or TEST has begun. A prelocked held-out representation/value probe should precede any fresh training campaign; a favorable probe is not itself a method result. Original goal criteria remain unchanged.

## Problem and evidence

V14's capacity-matched joint-unserved identity term did not improve reliably (−1.72 CI95[−7.08,+2.80]) despite a near-rollout aggregate DEV point estimate. Its deficits in interchangeable/reciprocal2 are about +47/+49 cost with roughly two extra H48 failures and more PM queue time. V15's exact PM-hazard release feature is active and changes 11.4% of same-bank choices, but its held-out Q advantage over an age-agnostic feature is only −0.269 CI95[−0.526,+0.001], far below the locked material gate, and reciprocal3 worsens. A single fixed risk formula is therefore not supported as the core addition. Earlier V8 held-out teacher fitting also found a generic flat/joint head weaker than a local shared head on its small diagnostic panel; a larger joint network alone is not justified. The remaining question is whether **the action's whole post-decision resource state** helps a learned value head predict the consequences of repeated dispatch, rather than forcing one analytic risk statistic.

## Core method and formulation

For each legal matching `a`, construct a current-information post-decision vector: worker residual times after any new service starts, served-machine flags, and for each machine the earliest compatible technician release under `a`. Preserve current machine/request/failure/age features, compatibility and duration edges, and WAIT. A shared action-value network `Q_theta(s,a)` embeds the current observation and matching incidence, then attends or pools across machine–technician relations conditioned on these post-decision release features. It predicts *relative* H48+tail16 economic cost against the old actor's action, rather than absolute trajectory cost, to remove large state-level offsets. At each decision, score every legal matching and choose the lowest predicted cost; no future shock, online planner, imitation label, fixed WAIT duration or hard shortest-duration restriction is used.

Train from scratch by approximate policy iteration: gather on-policy states; estimate full-H64 old-policy root Q values on common stochastic scenarios exactly as V14; fit the shared action-value head by a paired within-state ranking/regression objective with a trust-region limit on the induced masked action distribution; repeat for a fixed update budget. This is model-based value learning from the agent's own simulator experience, not planner imitation or pretraining. Evaluate inference time including all legal root scores.

## Why it fits and controlled alternative

Technician service commitments are nonpreemptive and have heterogeneous durations/compatibility. A matching can leave one machine without any compatible technician for several ticks even when another worker is free. The post-decision vector exposes **which** resources become occupied and when each machine can next receive service; a learned head can combine this with PM-to-CM risk, failed-machine downtime, queued requests and case costs. V15 showed a scalar hazard projection is too weak or too correlated with its control. The principal ablation uses the *same* observation, action incidence, edge features, network parameter count and Q training bank, but supplies an action-independent **pre-decision** release vector in the extra channels. Because it still sees the full state and action matrix, this is an inductive-bias control rather than information deprivation. Verify equal gradient-active capacity and matched actual forecast/training compute, with divergent on-policy states disclosed.

## Prior work boundary

[Learning to Dispatch](https://proceedings.nips.cc/paper/2020/file/11958dfee29b6709f48a9ba0387a2431-Paper.pdf) already learns structured dispatch policies; [HetGPO/AirME](https://ojs.aaai.org/index.php/ICAPS/article/view/19839) already models stochastic maintenance resource decisions. [Value Function Based Production Scheduling](https://publications.ri.cmu.edu/value-function-based-production-scheduling) and subsequent RL work establish value-function scheduling, and post-decision state value methods are known in resource allocation. A V16 claim could only be the specific *compatible-release-conditioned matching value representation*, if a fair active-capacity ablation and competitive fresh evaluation support it. No claim of inventing Q learning, post-decision states, graph scheduling or hazard-aware maintenance follows from this proposal; targeted primary-source comparison must expand before any publication claim.

## Falsifiable plan and gates

First, prelock a supervised **diagnostic** on immutable V14 training root Q banks: five leave-one-training-seed-out folds, identical sized post-decision and pre-decision heads, fixed sample/update/regularization budget, held-out full-legal-action root selection regret under the saved old-policy Q, and uncertainty over seeds/states. Include simple existing V14 logit and risk choices. Require a material, seed-consistent held-out benefit and no collapse to WAIT before investing in a fresh RL campaign. This probe can reject representational promise, but cannot prove closed-loop value because its Q uses old V14 continuation and four scenarios. If it fails, retire V16 rather than merely enlarging the model.

If it passes, freeze a new disjoint five-training-seed scratch-RL DEV protocol with fixed update/forecast budget, equal-capacity pre-decision ablation, flat PPO, V14 count/joint, V7 structured, FCFS, risk matching and bounded rollout on fresh physical seeds. Require robust ablation gain across strong and weak seeds, near-rollout cost, ≥10× inference speed and no simple heuristic cost/runtime dominance before independent replication and a single frozen fresh TEST. Report every case, failures/queues/availability, training and inference compute, failure episodes and seed-level uncertainty. Keep the user goal's ≥5% strongest-comparator or ≤1% planner-cost route unchanged.
