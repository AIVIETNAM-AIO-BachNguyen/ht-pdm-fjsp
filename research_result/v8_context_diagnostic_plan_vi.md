# DEV-only diagnostic plan: absent-request machine context in shared actor

Written 2026-10-20 **before implementing or running** this diagnostic. This is an exploratory mechanism test, not a new confirmation or a method proposal. V7 opened TEST seeds are excluded. No PPO training, no physics/objective edits, no new architecture and no goal-completion claim from this diagnostic.

## Hypothesis and discriminating observation

The V6/V7 shared actor computes each edge score from clock, that edge's machine/technician embeddings and edge features, and sums scores in each matching. A healthy machine without a current request cannot occur in any legal matching. Its age can therefore change without changing any **legal** shared actor logit. This structural invariant may matter if approaching PM demand makes reserving a technician, choosing a shorter service or reprioritizing a current request valuable. The central empirical question is whether a current-information bounded planner changes its preferred legal root matching across such paired states with a material forecast-cost margin. An invariant actor would be unable to follow that change. The flat 56-feature MLP is a representation control; it can in principle react, but may not have learned to.

## Source states and paired intervention

Use the unchanged four V7 N4/K2 cases, H48+tail16 simulator, threshold requester and current information only. DEV diagnostic physical seeds **69000000–69000031** (32/case); smoke seeds **69010000–69010001**; forecast stream anchor **69020000**. Reject overlap with registered seeds. Generate complete H48 trajectories on each case/seed from six fixed source controllers: risk matching and **all five** DEV-selected `shared_canonical` V7 checkpoints. This broadens state coverage without choosing a favorable replica. For each pre-action state at tick 4–41, after fixed threshold admission, mark eligible if at least one queued request, at least two legal matchings, and at least one healthy, unassigned, no-request machine with age ≤1. Choose the lowest-index such machine; create a paired state with only that machine's age set to 2. Require both request states pass validation and have identical request submissions, legal matching catalogue/mask, technician state and current requests. At age 2 it is still below the threshold age 3, so it remains request-free at the root. The branch state is a valid current state, though not asserted to be the same trajectory under a common past.

For each (case, source controller) stratum, rank eligible state identifiers by SHA256 of fixed literal `v8-context-diagnostic:case:source:physical_seed:tick:machine`, retain the first **16**; no outcome-dependent selection. If fewer than 16 exist, use all and record deficit; do not expand seeds. Maximum 4×6×16=384 pairs. Report eligible-state frequency per stratum and selected diversity. No second pass that changes sampling after seeing planner outcomes.

## Probe, metrics and stopping

For each selected pair, evaluate the *same* current-information bounded rollout planner (`requester=threshold`, 16 independently sampled forecast scenarios, 6-tick horizon, risk-matching continuation) on both states with a common forecast seed derived from anchor 69020000 and pair identifier. Record all root-action expected costs, chosen action and best-vs-runner-up margin. Define a **material planner flip** as different chosen legal matching with both original and perturbed root-action advantage over the alternative action ≥5.0 economic cost units over the bounded forecast window; also report flips at 1 and 10 units and the full margin distribution. This threshold is a descriptive diagnostic, not a confirmatory significance test. Report paired forecast root-score differences and whether change comes from request creation during the window. Bounded rollout is not an optimal oracle.

Replay the selected V7 `shared_free`, `shared_canonical` and `flat_free` checkpoints for **all five training seeds** on each paired state, with their correct free/canonical masks. Record selected actions, legal-action logits for shared actors, exact logit error, and disagreement with planner. Record state-level score regret relative to the minimum root expected cost; this is six-tick forecast regret on common states, **not** closed-loop economic cost. Count policy action flips and their overlap with material planner flips. Do not infer that flat's ability to read all coordinates implies it uses them. Critic outputs are not actor evidence.

One smoke (2 physical seeds/case, max 2 pairs/stratum, 4 forecast scenarios) verifies state invariants, deterministic replay, source checkpoint hashes, non-overlap and CSV/JSON schema. Then commit/push verified code/plan before a single full DEV diagnostic. Full stops at 40 minutes; smoke at 5 minutes. Show tqdm during trajectory generation and paired evaluation. Each run uses new timestamped `research_result/v8_context_{smoke|dev}_.../` directory and refuses an existing path. Store manifest with source commit/hashes, checkpoint/selection hashes, seeds, case/config, counts, runtime and output hashes; store selected pair snapshots, per-pair planner/policy CSV/JSONL and summary. Keep raw outside Git, compact report in Git. If material planner flips are absent or too rare, do not add context aggregation simply because an architectural invariant exists; investigate action/headroom or learning instead.
