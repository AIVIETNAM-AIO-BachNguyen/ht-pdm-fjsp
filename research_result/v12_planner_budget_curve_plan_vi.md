# Prelock: budgeted planner-correction curve on opened V12 DEV

Locked after independently audited one-action/WAIT-four result `861c334`, before computation. Question: can a small number of *state-specific* bounded-planner corrections recover enough of the selected V12 actor's long-horizon gap to support a learned RL consultation/resource-reservation mechanism? This is an **oracle diagnostic**, not a deployable controller, method ablation, fresh TEST or independent replication. A learner must later infer when to consult and must show RL-specific benefit; planner imitation cannot be the main axis.

Use immutable selected V12 reliability-credit checkpoints for five train seeds71500000–04, opened DEV physical seeds71510000–15, target cases interchangeable scale1 and reciprocal scale2, same threshold requester and H48+tail objective. Evaluate deterministic actor with correction budgets K∈{0,1,2,4}. At each tick while fewer than K corrections have been used, compute the actor and locked 16-scenario six-tick bounded-planner action on the **current same state**. If actions differ, execute planner action and count one correction; if equal, execute actor action. Once K corrections are used, execute actor alone. K0 equals selected actor. K1 must match the previously audited single-action intervention exactly episode by episode. For a pair with fewer than K disagreements, the oracle keeps querying until H48. No fixed WAIT hold, shortest-duration restriction or altered physics.

Only the two target cases here, reported separately: mean H+tail cost for each K, ratio to full rollout, fraction of actor−rollout gap recovered, training-seed distribution and 20,000-draw hierarchical bootstrap over five train seeds/16 physical tapes with fixed seed 71590000; operational metrics (H failures/availability, queued CM/PM ticks, starts, cost parts). Use full source rollout episodes from V12 (audited) and replay K0/K1 against immutable V12 and prior intervention rows. No timing claim based on oracle correction count alone: queries at matching states still cost compute.

Directional gate: a sparse-consultation RL mechanism has cost headroom only if K≤4 reaches within 1% of rollout cost in **both** cases pooled and in ≥4/5 training seeds per case. Direct oracle execution has runtime headroom only if mean total selection time is ≤0.1× full rollout in both cases. If cost headroom fails, reject sparse planner consultation as the main method direction here; if cost passes but runtime fails, only a learned low-cost trigger could qualify. These diagnostic gates are stricter than the eventual aggregate A/B criterion and do not complete the goal.
